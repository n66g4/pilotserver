# PilotServer 统一管理控制台与中英文设计

## 目标

将现有管理页重组为连贯的单页控制台，使“服务状态 → 设备 → 行程 → 回放”形成稳定的信息层级；同时为所有用户可见文案提供完整的简体中文和英文切换。

本次仅调整管理端前端，不修改现有 HTTP API、认证协议、回放协议或遥测数据结构。

## 设计方向

采用已确认的 A「统一控制台」布局：

- 桌面端使用左侧主导航、顶部状态栏和右侧主工作区。
- 移动端将主导航收为底部四项导航，主工作区保持单列。
- 回放在主工作区内打开，保留全局导航、当前设备和当前行程上下文。
- 使用深墨绿色、暖灰背景和青绿色状态强调，延续回放页面的技术仪表风格。
- 不加载外部字体；优先使用系统已有的中西文字体组合，避免管理页因 CDN 失败退化。

## 信息架构

### 顶部状态栏

- PilotServer 品牌
- 当前服务状态
- 当前在线设备数
- 中文 / English 切换
- 退出登录

### 概览

- 在线设备数
- 已存行程数
- 当前地图和局域网访问状态
- 当前公网地址、局域网访问和地图提供商摘要
- 最近行程快捷入口

概览只请求设备列表、每台设备的行程列表和现有设置，不批量请求回放摘要，
避免首次打开管理页触发全库 qlog 解析。遥测健康信息仅在用户打开具体行程后计算。

### 设备

- 设备标识和在线状态
- 查看行程
- 开启 SSH
- 最近同步状态

“刷新设备”不再作为孤立主操作，而是设备页标题旁的次级刷新按钮。

### 行程

- 保留当前设备上下文
- 行程列表只展示现有轻量元数据；不为每条行程预加载摘要
- 点击行程后在当前工作区加载文件和摘要，展示分段数量、视频可用性和遥测健康状态
- 选中行程区分“全部正常”“部分分段损坏”“无遥测”和“正在加载”

### 设置

- PUBLIC_BASE_URL
- LISTEN
- 局域网直连
- 地图提供商、Web Key 和安全码

设置独立成页，保存结果和校验错误在表单附近显示，不再与设备操作混排。

### 回放

- 保留左侧导航和顶部状态栏
- 标题区展示设备、行程和返回行程列表操作
- 视频为主视觉
- 播放模式、分段导航和错误恢复集中在视频控制区
- VEHICLE SPEED、CONTROL STATE、SYSTEM FLAGS、CURRENT ALERT、轨迹和曲线统一使用当前语言
- 分段损坏提示明确说明仅影响相应分段，不将部分失败描述为整条行程失败

## 国际化

### 语言选择

- 首次访问根据 `navigator.languages` / `navigator.language` 判断：以 `zh` 开头使用简体中文，否则使用英文。
- 用户手动切换后写入 `localStorage`，后续优先使用保存值。
- 登录和退出不会清除语言选择。
- 根元素同步设置 `lang="zh-CN"` 或 `lang="en"`。

### 文案组织

- 在管理页脚本中维护扁平的 `zh-CN` / `en` 文案字典和统一 `t(key, params)` 函数。
- 静态节点使用 `data-i18n`、`data-i18n-placeholder` 和 `data-i18n-aria-label`。
- 动态设备、行程、回放、遥测和错误文案必须通过 `t()` 生成。
- API 返回的稳定状态码和内部错误码不直接展示；先映射为本地化文案。
- 路径、dongle ID、route ID、环境变量名、数值和标准缩写保持原样。

切换语言时原地重绘当前视图，不重新登录、不重新请求媒体票据、不重置视频播放位置。

## 前端状态与组件边界

继续使用现有原生 HTML/CSS/JavaScript，不引入框架。

- `appState`：当前页面、语言、设备、行程、回放选择和异步请求代次。
- `setView(view)`：切换概览、设备、行程、设置和回放工作区。
- `renderShell()`：更新导航、顶栏和当前页面标题。
- 现有设备、行程和回放函数保留数据请求职责，渲染输出接入统一壳层和 `t()`。
- `telemetry.js` 接收翻译函数或本地化文案集合，不自行混用中英文常量。

异步响应继续使用 generation 检查，旧页面返回的数据不得覆盖新页面。退出和 401 流程清理业务状态、回放实例和请求代次，但保留语言设置。

## 响应式与可访问性

- 桌面主导航固定在左侧，主工作区使用受限最大宽度。
- 小于 760px 时变为底部导航；表格改为卡片；设置表单和回放遥测改为单列。
- 交互目标最小 40px。
- 导航使用真实按钮或链接，并提供 `aria-current`。
- 状态不能只依赖颜色，同时显示文字或图标。
- 支持键盘导航、可见焦点和 `prefers-reduced-motion`。
- 中英文切换后保持当前焦点或将焦点落到新页面标题。

## 错误处理

- 页面级错误显示在对应工作区，不覆盖其他页面。
- 保存设置错误显示在设置表单附近。
- 设备刷新错误保留已有列表并提示刷新失败。
- 部分遥测失败保留正常分段，并显示失败数量和分段号。
- 地图 SDK 失败回退无底图轨迹。
- 未知错误使用本地化通用文案，同时保留现有 HTTP 状态处理。

## 测试与验收

### 自动测试

- 首次语言跟随浏览器。
- 保存语言优先且切换后持久化。
- 静态、placeholder、aria 和动态错误文案均可切换。
- 语言切换不重置视频时间和当前行程。
- 导航切换及退出/401 状态清理。
- 设备刷新不会清空已有数据。
- 部分遥测失败文案不再暗示整条行程失败。
- `telemetry.js` 的 HUD、地图和曲线状态使用当前语言。

### 浏览器验收

- 桌面宽屏：概览、设备、行程、设置、回放完整流程。
- Android Chrome 和 iPhone Safari 尺寸：底部导航、触控目标、视频和遥测单列布局。
- 中文和英文各完成一次登录、设置、行程浏览和回放流程。
- 回放过程中切换语言，视频位置、模式、分段和遥测保持不变。
- 地图未配置、地图失败、无 GPS、部分遥测损坏等状态均有一致文案。

## 发布

- SPK 默认版本从 `1.0.18-1` 提升为 `1.0.19-1`。
- 保留原生和 Linux/amd64 可执行文件构建、全量 Go/Node 测试、浏览器冒烟和 SPK 内容检查。
- 升级只替换前端与可执行文件，不迁移数据库，也不改变现有配置。
